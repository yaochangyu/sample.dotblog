# 23: 業務 API 資料庫與跨執行個體的業務冪等

**What to build:** 訂單、冪等紀錄、處理中租約與業務唯一鍵從程序內暫存改存到業務 API 自己的 PostgreSQL 資料庫。兩個業務 API 執行個體共用這個資料庫時，同一筆業務操作（相同 Idempotency Key 或相同業務識別）併發送達只會建立一筆訂單，租約逾期後其他執行個體可接手。業務 API 重啟後訂單與去重狀態仍在。

**Blocked by:** 22 — 真實儲存的測試基礎與故障注入。

**Status:** closed

- [x] 兩個執行個體併發提交同一業務操作，本地副作用只提交一次；另一個回既有結果或處理中；內容不同者拒絕且不覆寫（AC-34）。
- [x] 處理中的租約逾期後由另一個執行個體重試可以接手且不產生重複副作用；租約未逾期前不得接手（AC-35）。
- [x] 去重以 Client 加業務識別、Client 加 Idempotency Key 的唯一性保證；Idempotency Key 紀錄過期後業務唯一性仍然成立（沿用 AC-09、AC-10、AC-11）。
- [x] 業務 API 重啟後，已建立的訂單與去重狀態仍然存在。
- [x] 資料庫不可用時，建單與去重相關請求回報服務錯誤且無業務副作用，不回應業務資料。
- [x] 現有業務冪等、資料範圍與取消訂單的 Scenario 全部維持通過，斷言不放寬。
- [x] 資料庫結構遷移進入版本控制，只有明確開啟設定時才在啟動時套用。
- [x] 隔離等級使用預設的 Read Committed，不依賴 Serializable。
- [x] 不實作 Gateway 相關項目；沿用已確認的 lab 範圍決定。
