# 28: 狀態儲存與跨執行個體的整體驗收

**What to build:** 以兩個授權伺服器執行個體與兩個業務 API 執行個體，共用各自的 PostgreSQL 資料庫與 Redis，端到端驗證 AC-31 到 AC-43 全部情境。這張票是收尾驗收，不新增功能；若驗收發現缺漏，回到對應票修正。

**Blocked by:** 23 — 業務 API 資料庫與跨執行個體的業務冪等；24 — Redis 防重放與防重放紀元；25 — 授權伺服器資料庫與管理操作的交易一致性；26 — 內部信任資料介面與撤銷傳遞；27 — 已驗證呼叫者稽核移到業務 API 資料庫。

**Status:** ready-for-agent

- [ ] AC-31 到 AC-43 每一條都有對應的 BDD Scenario 並實際通過，完整測試套件 0 失敗。
- [ ] 有一條端到端 Scenario：已登錄 Client 在其中一個授權伺服器執行個體申請並經管理員核准，新憑證取得 Token，經兩個業務 API 執行個體呼叫成功；撤銷後兩個執行個體都在新時效內阻擋。
- [ ] 資料庫帳號隔離：業務 API 以自己的帳號存取授權伺服器資料庫、或授權伺服器存取業務 API 資料庫，都被拒絕（AC-43）。
- [ ] 沒有任何服務仍依賴程序內共用物件取得信任資料、nonce 或訂單狀態。
- [ ] 實測並記錄各類撤銷的實際最慢生效時間，確認不超過 60 秒。
- [ ] 列出所有「待使用者確認」的 lab 暫定值：信任資料快取 TTL、信任資料介面路徑與格式、Redis 持久化設定、稽核保存期。
