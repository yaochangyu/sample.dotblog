# 24: Redis 防重放與防重放紀元

**What to build:** 請求簽章的 nonce 防重放改由 Redis 提供，登錄是原子的，並在多個業務 API 執行個體之間一致。Redis 紀錄遺失（重啟或被清空）時，防重放紀元重設為當下，簽章建立時間早於紀元的請求一律被拒絕；呼叫端用新 nonce 與新時間重簽即可通過。Redis 不可用時 Fail Closed。

**Blocked by:** 22 — 真實儲存的測試基礎與故障注入。

**Status:** ready-for-agent

- [ ] 同一份簽章併發送往兩個業務 API 執行個體，只有一個通過防重放，另一個被拒絕且無業務副作用（AC-31，強化 AC-08）。
- [ ] Redis 被清空或重啟後，重放遺失前建立的簽章被拒絕且無業務副作用；紀元之後建立的簽章照常通過（AC-32）。
- [ ] 被紀元拒絕的呼叫端以新 nonce 與新時間重簽後可以通過。
- [ ] Redis 不可用時請求被拒絕並明確回報服務錯誤，無業務副作用（AC-33，沿用 AC-05 的 Fail Closed）。
- [ ] nonce 保存期涵蓋簽章接受期限加時鐘容差；合法重試重簽換新 nonce 仍可通過（沿用既有簽章與防重放 Scenario）。
- [ ] nonce 登錄後若後續業務提交失敗，不回收 nonce；同一份簽章重送仍被擋，合法重試必須重簽。
- [ ] 先驗證簽章、摘要與時間，通過後才登錄 nonce，未驗證的請求不污染 nonce 紀錄。
- [ ] 現有簽章與防重放的 Scenario 全部維持通過，斷言不放寬。
- [ ] Redis 是否啟用持久化屬未定營運設定，本票不自行決定，紀錄為待確認。
- [ ] 不實作 Gateway 相關項目；沿用已確認的 lab 範圍決定。
