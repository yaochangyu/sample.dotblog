# 09: 安全追查已驗證呼叫者

**What to build:** 維護者可從一筆請求追查已驗證 Client、憑證／簽章金鑰、操作與結果；失敗請求不能偽造可信身分紀錄，紀錄也不洩漏認證或敏感業務資訊。

**Blocked by:** 03 — 業務 API 驗證原始呼叫端請求簽章。

**Status:** ready-for-agent

- [ ] 成功驗證的呼叫紀錄包含已驗證 Client、必要金鑰識別、操作、結果與關聯識別。
- [ ] 認證或驗簽失敗時，請求宣稱的 Client 身分標示為未驗證，不與已驗證呼叫者混淆。
- [ ] 紀錄不含原始 Token、私鑰或完整敏感 Body；檢查錯誤、診斷與簽章驗證紀錄也符合要求。
- [ ] 防止簽章基底或包含 Token 的標頭透過除錯資訊洩漏。
- [ ] 安全稽核紀錄與必要業務去重狀態分開管理；保存期及存取規則取得確認。
- [ ] 透過成功、失敗及偽造身分的整合情境，驗證紀錄可正確關聯且不含禁止資料。
- [ ] 紀錄失敗不被靜默吞掉或假報成功，依已確認的專案錯誤處理契約回報。

對應驗收：AC-14。
