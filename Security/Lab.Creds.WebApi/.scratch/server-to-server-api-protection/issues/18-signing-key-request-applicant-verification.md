# 18: 簽章金鑰登錄申請的申請者驗證與持有證明

**What to build:** 簽章金鑰登錄申請端點套用同一套申請者驗證：只有已登錄且狀態有效的 Client 能以現有憑證經 mTLS 驗證身分，並只能為自己申請。持有證明改為以所申請的新金鑰對申請內容簽章，證明失敗不建立待核准紀錄。待核准紀錄帶已驗證的申請者身分。與憑證申請各自獨立，兩者的驗證結果互不連動。

**Blocked by:** 17 — 憑證登錄申請的申請者驗證與持有證明；13 — 簽章金鑰登錄申請與核准。

**Status:** ready-for-agent

- [ ] 未經驗證送出簽章金鑰申請時被拒絕，不建立待核准紀錄（AC-24）。
- [ ] 以自己的身分替其他 Client 提出簽章金鑰申請時被拒絕（AC-25）。
- [ ] 申請簽章金鑰但無法以該金鑰對申請內容簽章時被拒絕，不建立待核准紀錄（AC-26）；簽章涵蓋範圍為 lab 暫定值並標註「待使用者確認」。
- [ ] 已登錄 Client 為自己申請並證明持有新金鑰時，建立待核准紀錄且帶已驗證的申請者身分（AC-27 簽章金鑰部分）。
- [ ] 被撤銷、停用或已退役憑證的 Client 提出申請時被拒絕（AC-29 簽章金鑰部分）。
- [ ] 失敗回應不洩漏其他 Client 的申請內容。
- [ ] 簽章金鑰申請與憑證申請的驗證互不連動：憑證申請通過不代表簽章金鑰申請通過。
- [ ] 每個驗收項目至少對應一個 BDD Scenario，先看到失敗再實作；沿用既有簽章規則與管理端點整合測試邊界。
