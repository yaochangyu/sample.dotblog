# 27: 已驗證呼叫者稽核移到業務 API 資料庫

**What to build:** 已驗證呼叫者稽核存入業務 API 資料庫。驗簽通過後先獨立提交稽核，回應送出時補上最終結果；業務提交失敗時稽核仍保留並記錄失敗結果。稽核寫入失敗時不建立訂單，回報服務錯誤。

**Blocked by:** 23 — 業務 API 資料庫與跨執行個體的業務冪等。

**Status:** ready-for-agent

- [ ] 兩個業務 API 執行個體處理的請求都寫入同一份稽核，可辨識已驗證呼叫者、簽章金鑰識別、操作與結果，且不含原始 Token、私鑰或完整敏感 Body（沿用 AC-14）。
- [ ] 業務提交失敗（例如衝突或儲存錯誤）時，稽核仍存在並記錄失敗結果。
- [ ] 稽核寫入失敗時不建立訂單，並明確回報服務錯誤（沿用 09 單的 Fail Closed）。
- [ ] 簽章未通過的請求，稽核中的 Client 只標為未驗證，不記成已驗證呼叫者。
- [ ] 業務 API 重啟後稽核仍然存在。
- [ ] 現有呼叫者稽核的 Scenario 全部維持通過，斷言不放寬。
- [ ] 稽核保存期與存取規則屬未定項目，本票不自行決定，紀錄為待確認。
- [ ] 不實作 Gateway 相關項目；沿用已確認的 lab 範圍決定。
