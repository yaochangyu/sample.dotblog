# 17: 憑證登錄申請的申請者驗證與持有證明

**What to build:** 憑證登錄申請端點不再接受匿名申請。只有已登錄且狀態有效的 Client，能以現有已核准的憑證經 mTLS 驗證身分後，為自己提出申請；宣稱的 Client 必須與已驗證的身分一致，不能替其他 Client 申請。申請者還必須證明持有所申請新憑證的私鑰，證明失敗的申請不建立待核准紀錄。待核准紀錄帶有已驗證的申請者身分，讓管理員核准時可以核對。被撤銷、停用或已退役憑證的 Client 不能申請。失敗回應不洩漏其他 Client 的申請內容，也不讓未驗證者區分「Client 不存在」與「身分驗證失敗」。

**Blocked by:** 11 — 管理介面與管理員身分驗證；12 — 憑證登錄申請與核准／拒絕。

**Status:** ready-for-agent

- [ ] 未經驗證（無憑證或未登錄憑證）送出憑證登錄申請時被拒絕，不建立待核准紀錄（AC-24）。
- [ ] 已登錄 Client 以自己的身分替其他 Client 提出申請時被拒絕，對方的待核准清單不變（AC-25）。
- [ ] 申請新憑證但無法證明持有對應私鑰時被拒絕，不建立待核准紀錄（AC-26）；持有證明的具體表示方式為 lab 暫定值並標註「待使用者確認」。
- [ ] 已登錄 Client 以現有憑證為自己申請並證明持有新私鑰時，建立待核准紀錄且帶已驗證的申請者身分（AC-27 憑證部分）。
- [ ] 被撤銷、停用或已退役憑證的 Client 提出申請時被拒絕（AC-29 憑證部分）。
- [ ] 失敗回應不洩漏其他 Client 的申請內容，且未驗證者無法區分「Client 不存在」與「身分驗證失敗」。
- [ ] 全新 Client 的首次登錄不在本票範圍，不自行假設其申請管道。
- [ ] 每個驗收項目至少對應一個 BDD Scenario，先看到失敗再實作；沿用管理端點為主要整合測試邊界，不新增測試介面。
