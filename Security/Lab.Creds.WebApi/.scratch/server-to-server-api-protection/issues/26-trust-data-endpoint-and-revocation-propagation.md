# 26: 內部信任資料介面與撤銷傳遞

**What to build:** 業務 API 不再與授權伺服器共用記憶體物件，改由授權伺服器的內部唯讀介面取得某 Client 的啟用狀態、有效憑證指紋與有效簽章公開金鑰，使用既有的 mTLS 服務身分呼叫，結果放程序內快取（TTL 10 秒，lab 暫定）。撤銷 Client、憑證或簽章金鑰後，所有業務 API 執行個體最慢一個快取 TTL 後阻擋；取不到信任資料且沒有有效快取時 Fail Closed。

**Blocked by:** 25 — 授權伺服器資料庫與管理操作的交易一致性。

**Status:** ready-for-agent

- [ ] 撤銷 Client、憑證或簽章金鑰後，各業務 API 執行個體最慢一個信任資料快取 TTL 後全部阻擋，且不超過 60 秒上限（AC-41，取代原本因共用記憶體而立即生效的行為）。
- [ ] Token 撤銷仍最慢等查證快取 TTL；兩層快取最壞相加仍在 60 秒內，驗收以實測確認。
- [ ] 業務 API 無法取得信任資料且沒有仍有效的快取時，拒絕處理並回應 503 `verification_unavailable`，無業務副作用（AC-42）。
- [ ] 信任資料介面只有已驗證的業務 API 服務身分能呼叫；Client 憑證、管理憑證與匿名呼叫被拒絕。
- [ ] 簽章金鑰歸屬判斷（keyid 必須屬於已驗證 Token 的 Client）在新資料來源下維持不變（沿用 AC-03）。
- [ ] 業務 API 不直接讀授權伺服器資料庫；信任資料一律經授權伺服器取得。
- [ ] 更新 07 單中「立即生效」的驗收敘述，記錄新的最慢時效與規格變動，不刪除原文。
- [ ] 現有撤銷、輪替與信任名單的 Scenario 維持通過；原本斷言「立即生效」者改為斷言新界線，並在票中說明。
- [ ] 信任資料介面的路徑與回應格式為 lab 暫定值，標註待使用者確認。
- [ ] 不實作 Gateway 相關項目；沿用已確認的 lab 範圍決定。
