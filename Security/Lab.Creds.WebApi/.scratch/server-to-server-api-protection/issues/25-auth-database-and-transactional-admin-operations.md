# 25: 授權伺服器資料庫與管理操作的交易一致性

**What to build:** 授權伺服器的 OpenIddict 資料、信任名單（憑證、簽章金鑰與其核准／退役／撤銷狀態、Client 啟用狀態）、登錄申請、持有證明 nonce 與管理操作稽核，全部改存到授權伺服器自己的 PostgreSQL 資料庫。管理操作的變更與 `accepted` 稽核放在同一個交易；套用失敗時整筆回滾並另寫一筆 `failed` 稽核。多個授權伺服器執行個體共用資料庫時，核准／拒絕、待核准上限與持有證明 nonce 在併發下仍然正確。

**Blocked by:** 22 — 真實儲存的測試基礎與故障注入。

**Status:** ready-for-agent

- [ ] 管理操作套用失敗時，信任名單與 `accepted` 稽核都不留下；留下一筆 `failed` 稽核；若 `failed` 稽核也寫不進去，回報稽核無法寫入（AC-36，取代原本已知缺口）。
- [ ] 稽核寫入失敗時管理操作不生效並回報服務錯誤（沿用 AC-22）。
- [ ] 兩位管理員或兩個授權伺服器執行個體同時核准、拒絕同一筆申請，只有一個決定生效，另一個得到「申請非待核准」的明確回應（AC-37）。
- [ ] 同一 Client 併發提交申請，待核准總數不超過上限（AC-38）。
- [ ] 同一份持有證明併發送出兩次，只建立一筆待核准申請，另一次被拒絕且不佔用額度（AC-39）。
- [ ] 授權伺服器重啟或由另一個執行個體接手後，信任名單、登錄申請、稽核與已核發的 Token 仍然有效且一致（AC-40）。
- [ ] OpenIddict 的 Client 登錄與信任名單在同一個資料庫與交易範圍內，核准後新憑證可取得 Token（沿用 AC-17）。
- [ ] 現有核准、拒絕、退役、撤銷、申請者驗證與稽核的 Scenario 全部維持通過，斷言不放寬。
- [ ] 資料庫結構遷移進入版本控制，只有明確開啟設定時才在啟動時套用；連線資訊走設定。
- [ ] 不實作 Gateway 相關項目；沿用已確認的 lab 範圍決定。
