# 06: 使用者 Token 撤銷與查證故障 fail closed

**What to build:** 使用者 Token 被撤銷或使用者被停用後，後續請求在既有的撤銷上限內被拒絕，不繞過查證。使用者 Token 的查證服務故障且沒有符合時效的有效快取時，拒絕處理並明確回報服務錯誤，不誤判為 Token 無效，也不造成業務副作用，沿用既有 fail closed 原則。

**Blocked by:** 03 — 呼叫者類型與 audience 隔離（禁止混用）。

**Status:** ready-for-agent

- [ ] 使用者 Token 被撤銷或使用者被停用後，既有撤銷上限內的後續請求被拒絕（AC-D11）。
- [ ] 使用者 Token 查證服務故障且無有效快取時，拒絕處理並明確回報服務錯誤，無業務副作用（AC-D12）。
- [ ] 故障回應與憑證或 Token 無效的回應可明確區分，不誤判為 Token 無效。
- [ ] 使用者撤銷與查證故障不影響服務路徑既有的撤銷與 fail closed 行為。
- [ ] 使用者 Token 的查證快取與撤銷同步機制為 lab 暫定值並標註「待使用者確認」。
- [ ] 每個驗收項目至少對應一個 BDD Scenario，實測撤銷延遲在上限內；先看到失敗再實作。
