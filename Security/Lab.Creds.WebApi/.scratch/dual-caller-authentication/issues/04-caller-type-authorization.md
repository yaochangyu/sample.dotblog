# 04: 授權依呼叫者類型分開

**What to build:** 授權規則依呼叫者類型分開定義：使用者只能操作自己的業務資料範圍；服務維持被核准的操作與業務資料範圍。服務的高權限不能用來代替使用者的權限限制（避免混淆代理人）。業務操作可以針對呼叫者類型設定允許或拒絕，寫入類或敏感操作可以只允許其中一種呼叫者。服務與使用者共用業務邏輯，但各自的 scope、角色與資料範圍語意不互相混用。

**Blocked by:** 03 — 呼叫者類型與 audience 隔離（禁止混用）。

**Status:** ready-for-agent

- [ ] 使用者要求他人的業務資料時被資料範圍授權拒絕（AC-D07）。
- [ ] 服務嘗試以自身高權限執行使用者專屬的限制操作時，依呼叫者類型授權規則被拒絕（AC-D08）。
- [ ] 限定單一呼叫者類型的操作，由另一類型呼叫時被拒絕（AC-D14）。
- [ ] 服務維持被核准的操作與業務資料範圍，不因新增使用者路徑而擴大。
- [ ] 使用者的資料範圍與角色模型為 lab 暫定值並標註「待使用者確認」，不自行視為已核准。
- [ ] 每個驗收項目至少對應一個 BDD Scenario，先看到失敗再實作。
