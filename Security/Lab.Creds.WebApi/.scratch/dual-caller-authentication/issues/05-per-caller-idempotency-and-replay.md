# 05: 冪等與防重放依呼叫者身分分開

**What to build:** 兩種呼叫者共用同一份業務邏輯與本地提交保證，但冪等去重與穩定業務識別依呼叫者類型與已驗證身分分開計算：同一業務識別由使用者與服務各自提交，互不覆蓋也不誤判為重複；使用者重試與併發提交同一業務操作時，本地副作用只提交一次。使用者寫入沒有請求簽章，因此仍需要防重放保護，不能因為缺簽章而讓寫入操作失去重放與冪等防護。

**Blocked by:** 03 — 呼叫者類型與 audience 隔離（禁止混用）。

**Status:** ready-for-agent

- [ ] 同一業務識別由使用者與服務各自提交時，各自獨立，不互相覆蓋或誤判重複（AC-D09）。
- [ ] 不同使用者提交相同識別時互不衝突，同一使用者範圍內業務識別唯一。
- [ ] 使用者重試或併發提交同一業務操作時，本地副作用只提交一次，回傳既有結果或處理狀態（AC-D10）。
- [ ] 使用者寫入請求有防重放保護；具體機制為 lab 暫定值並標註「待使用者確認」，spec 未定義不自行視為已核准。
- [ ] 服務路徑既有的 nonce、冪等與業務唯一性行為不變。
- [ ] 每個驗收項目至少對應一個 BDD Scenario，先看到失敗再實作。
