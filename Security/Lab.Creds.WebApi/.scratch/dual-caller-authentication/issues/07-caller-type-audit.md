# 07: 稽核區分呼叫者類型

**What to build:** 追查紀錄記錄已驗證呼叫者的類型與身分、操作與結果，能分辨是服務呼叫還是使用者呼叫。使用者請求不會被記成服務，服務請求不會被記成使用者。驗證失敗的請求，其宣稱的呼叫者類型與身分只標為未驗證，不記成已驗證呼叫者。紀錄不含原始 Token 與私鑰，稽核寫入失敗的處理沿用既有 fail closed 原則。

**Blocked by:** 03 — 呼叫者類型與 audience 隔離（禁止混用）。

**Status:** ready-for-agent

- [ ] 稽核記錄已驗證呼叫者的類型與身分，可區分服務呼叫與使用者呼叫（AC-D13）。
- [ ] 驗證失敗者的宣稱呼叫者類型與身分只標為未驗證，不記成已驗證（AC-D13）。
- [ ] 紀錄不含原始 Token、私鑰與完整敏感 Body（AC-D13）。
- [ ] 稽核寫入失敗時，沿用既有 fail closed：不放行業務操作並明確回報服務錯誤。
- [ ] 沿用既有呼叫者安全稽核的保存與存取規則；新增欄位為 lab 暫定值並標註「待使用者確認」。
- [ ] 每個驗收項目至少對應一個 BDD Scenario，先看到失敗再實作。
