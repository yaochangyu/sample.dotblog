# 08: 雙呼叫者的整體驗收與文件

**What to build:** 以「同一業務端點同時接受服務呼叫與使用者呼叫」為主題，端到端驗證 AC-D01 到 AC-D14 全部情境，並更新領域詞彙與 ADR，讓兩種呼叫者的驗證分離決定、lab 例外與尚未決定的項目有明確紀錄。這張票是收尾驗收，不新增功能；若驗收發現缺漏，回到對應票修正。

**Blocked by:** 04 — 授權依呼叫者類型分開；05 — 冪等與防重放依呼叫者身分分開；06 — 使用者 Token 撤銷與查證故障 fail closed；07 — 稽核區分呼叫者類型。

**Status:** ready-for-agent

- [ ] AC-D01 到 AC-D14 每一條都有對應的 BDD Scenario 並實際通過，完整測試套件 0 失敗。
- [ ] 有一條端到端 Scenario：同一個建立訂單端點，服務與使用者各自成功呼叫；混用 Token、越權資料、重試與撤銷都被正確處理。
- [ ] `GLOSSARY.md` 補上本需求新增的詞彙（呼叫者類型、使用者呼叫者），並與既有「呼叫服務」「Client 身分」「已驗證呼叫者」區分。
- [ ] ADR 補記本需求的 lab 例外與限制（測試使用者帳號、程序內儲存、使用者路徑無請求簽章）。
- [ ] 列出所有「待使用者確認」的 lab 暫定值：使用者 Token 效期與表示方式、使用者防重放機制、角色與資料範圍、撤銷傳播、錯誤格式。
- [ ] 不實作 Gateway、委託與 token exchange；沿用已確認的 lab 範圍決定。
